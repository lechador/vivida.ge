# Vivida-ს ვებ აპის დაყენების გეგმა

განახლდა: 2026-09-23. ეს გეგმა ეხება `vivida.ge`-ის ბრაუზერიდან მთავარ ეკრანზე დაყენებას (PWA). Flutter-ის მობილური აპი არ არის გაშვებული; Android-ის მაღაზიის ვერსია unpublished არის და ახლო მომავალში მისი დაბრუნება არ იგეგმება.

## შესრულების სტატუსი

დამატებულია ფუტერისა და ავტორიზებული მომხმარებლის მობილური მენიუს ინსტალაციის მოქმედება, Android-ის სისტემური prompt და ხელით დაყენების ინსტრუქცია, ღირებული მოქმედების შემდეგ კონტექსტური შეთავაზება 30-დღიანი გადადებით, გაუმჭვირვალე PNG/`maskable` ხატულები, მომსახურე სკრიპტის რეგისტრაცია და offline შეტყობინება, GA4 მოვლენები, პირველი მხარის აღრიცხვის ცხრილი/მიგრაცია და `vivida-admin`-ის PWA გვერდი. ორივე მონაცემთა წყარო ითვლის მხოლოდ ანალიტიკაზე თანხმობის მქონე მომხმარებლებს. გამოქვეყნებამდე საჭიროა მიგრაცია `0085` და GA4 გასაღებები მხოლოდ სურვილის შემთხვევაში, თუ ინსტალაციის გზის დამატებითი ანალიზი გვინდა.

## რა გვაქვს დღეს

- `app/manifest.ts` აცხადებს `standalone` რეჟიმს და უკვე იყენებს 192/512 PNG და `maskable` ხატულებს. `app/apple-icon.png`-იც გაუმჭვირვალეა; მოწყობილობაზე საბოლოო ხილვადობა დასამოწმებელია.
- `public/sw.js` push შეტყობინებებთან ერთად გვერდის offline შეტყობინებასაც აბრუნებს; სრული offline ფუნქციონალი ცალკე სამუშაოა.
- დაყენების ღილაკი ფუტერსა და მობილურ მენიუშია. Footer-იდან App Store/Play Store-ის „მალე“ ნიშნები ამოღებულია.
- `lib/analytics.ts`-ში PWA მოვლენები დამატებულია. `vivida-admin`-ის PWA გვერდი პირველი მხარის ბაზის რაოდენობასა და სურვილის შემთხვევაში GA4-ის ინსტალაციის გზას ცალ-ცალკე აჩვენებს; ორივე თანხმობაზეა დამოკიდებული.

## 1. ინსტალაციის შეთავაზება

1. Footer-ის ახალი ვებ აპის ტექსტს დაემატოს „დაამატე Vivida მთავარ ეკრანზე“ მოქმედება; იგივე მოქმედება მობილურ მენიუში განთავსდეს. ტექსტში ნათლად ეწეროს, რომ ეს ვებ აპია.
2. Android-ის მხარდაჭერილ ბრაუზერში `beforeinstallprompt` მოვლენა შეინახოს კლიენტმა და ღილაკზე დაჭერისას გამოიძახოს ბრაუზერის ინსტალაციის დიალოგი. თუ მოვლენა არ მოვიდა, ღილაკმა მხოლოდ შესაბამისი ბრაუზერის მენიუს ინსტრუქცია აჩვენოს. უარყოფის შემდეგ იმავე სესიაში აღარ შეაწუხოს მომხმარებელი.
3. iPhone/iPad-ზე, სადაც პროგრამული prompt არ არის ხელმისაწვდომი, ღილაკმა აჩვენოს მოკლე, ვიზუალური Safari → Share → Add to Home Screen ინსტრუქცია. უკვე standalone რეჟიმში გახსნილ აპში ინსტალაციის შეთავაზება დაიმალოს.
4. ერთი კონტექსტური შეთავაზება გამოჩნდეს მხოლოდ მას შემდეგ, რაც მომხმარებელმა ღირებული მოქმედება შეასრულა (მაგალითად, პირველი რუკის დათვალიერება ან ტაროს პასუხი). უარყოფისას დაიმახსოვროს გადადება და აღარ აჩვენოს ხშირად.
5. გადაამოწმოს Android Chrome, iOS Safari, desktop Chrome/Edge და unsupported ბრაუზერები: ღილაკი ყოველთვის სწორ მოქმედებას უნდა ასრულებდეს და არ უნდა ჰპირდებოდეს მაღაზიის აპს.

## 2. ხატულის გასწორება

1. არსებული Vivida-ს ვარსკვლავისგან შეიქმნას სრულფონიანი, გაუმჭვირვალე 192×192 და 512×512 PNG, ასევე ცალკე `maskable` ვარიანტები. ფონი უნდა ავსებდეს მთელ კვადრატს; ლოგოს მნიშვნელოვანი ნაწილი ნიღბის უსაფრთხო არეში დარჩეს.
2. `app/manifest.ts`-ში ჩაიწეროს ეს ფაილები შესაბამისი `purpose` მნიშვნელობებით. `app/apple-icon.png` განახლდეს გაუმჭვირვალე 180×180 ვერსიად. Favicon-იც იგივე ბრენდს უნდა შეესაბამებოდეს.
3. ახალი ხატულა შემოწმდეს Android-ის სხვადასხვა ფორმის ნიღბით და iPhone-ის მთავარ ეკრანზე, ღია და მუქ ფონზე. ძველი დაინსტალირებული ვერსია შეიძლება ქეშში დარჩეს; შემოწმება ახალ დაყენებაზეც უნდა ჩატარდეს.

## 3. სტატისტიკა ადმინ პანელში

1. გაიწეროს მოვლენები: `pwa_install_cta_viewed`, `pwa_install_cta_clicked`, `pwa_install_prompt_shown`, `pwa_install_prompt_accepted`, `pwa_install_prompt_dismissed`, `pwa_appinstalled`, `pwa_standalone_opened`. პარამეტრები იყოს მხოლოდ პლატფორმა, ბრაუზერი, ენა და ჩვენების ადგილი; პირადი მონაცემები GA4-ში არ გაიგზავნოს.
2. სწრაფი ხედისთვის GA4 Data API-დან `eventName`/`eventCount` გამოიყენოს `vivida-admin`-ის Audience ან ცალკე PWA გვერდმა: შეთავაზების ნახვა → დაჭერა → მიღება → standalone გახსნა, დროის დიაპაზონით და პლატფორმით. ეს რიცხვები მხოლოდ თანხმობის მქონე მომხმარებლებს მოიცავს.
3. პირველი მხარის endpoint და ცხრილი ინახავს შემთხვევით install ID-ს, პირველი standalone გახსნის თარიღსა და ბოლო გახსნის თარიღს მხოლოდ ანალიტიკაზე თანხმობის შემდეგ. Android-ის `appinstalled` ცალკე GA4 მოვლენაა და ბაზის პირველ გახსნას არ უდრის; iOS-ზე პროგრამული ინსტალაციის მოვლენა არ არის. endpoint-ს აქვს ვალიდაცია და rate limit, ჩანაწერი ბოლო გახსნიდან 13 თვეში იშლება, `vivida-admin` კი მხოლოდ კითხულობს.
4. ადმინში სათაურები ზუსტად ასახავდეს მეტრიკას: **დაფიქსირებული ინსტალაციები**, **უნიკალური standalone მოწყობილობები**, **აქტიური standalone მოწყობილობები ბოლო 30 დღეში**, **CTA → ინსტალაციის კონვერსია**. ცალკე აღინიშნოს თარიღი, საიდანაც დათვლა დაიწყო.
5. „რამდენს აქვს ახლა დაყენებული“ ზუსტად ვერ განისაზღვრება: ბრაუზერი ყველა პლატფორმაზე არ გვაძლევს დაყენების/წაშლის სრულ სიას. `appinstalled` ძირითადად Chromium-ის სიგნალია, iOS-ზე კი პირველი standalone გახსნა მხოლოდ მიახლოებაა. მონაცემთა წაშლამ ან ხელახლა დაყენებამ შეიძლება ახალი ID შექმნას; ერთ ადამიანს რამდენიმე მოწყობილობა შეიძლება ჰქონდეს. ამიტომ ეს მეტრიკა მოწყობილობების დაკვირვებული რაოდენობაა და არა ადამიანების ან მიმდინარე ინსტალაციების ზუსტი რიცხვი.

## თანმიმდევრობა და მიღების კრიტერიუმი

ჯერ გასწორდეს ხატულა და ინსტალაციის მოქმედება, შემდეგ დაემატოს მოვლენები და ადმინის ხედები. წარმატება ნიშნავს: Android-ზე ერთი დაჭერით იხსნება ბრაუზერის დიალოგი, iOS-ზე ჩანს გასაგები ინსტრუქცია, უკვე დაყენებულ აპში შეთავაზება ქრება, ხატულას თეთრი გვერდები არ აქვს და ადმინი აჩვენებს დათვლის დაწყების შემდეგ დაფიქსირებულ ინსტალაციებს მკაფიო საზღვრებით.

საყრდენი დოკუმენტაცია: [web.dev — installation prompt](https://web.dev/learn/pwa/installation-prompt/), [MDN — install prompt](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Trigger_install_prompt), [Apple — Home Screen icon](https://developer.apple.com/videos/play/wwdc2022/10048/), [Google Analytics Data API](https://developers.google.com/analytics/devguides/reporting/data/v1).
